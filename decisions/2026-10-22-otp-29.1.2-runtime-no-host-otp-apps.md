# Runtime rebuilt on OTP 29.1.2 / OpenSSL 3.5.9; no host OTP apps on the device

- Date: 2026-10-22
- Status: accepted
- Issues: MOB-493, MOB-494

## Context

The `otp-5c9c69fc` runtime was OTP 29.0 with OpenSSL 3.4.0. It lacked 47 OTP
security fixes (two of them critical TLS client bugs), and OpenSSL 3.4.0
lacked 55 CVEs, with the 3.4 branch going end-of-life on 2026-10-22. The
29.0.x line no longer gets patches, so the fix is the newest 29.x (29.1.2)
with OpenSSL on the 3.5 LTS branch.

While verifying the new runtime on a phone, `code:which(ssl)` turned out to
point at `files/otp/<app>/ssl.beam` instead of the runtime's
`lib/ssl-11.7.8`. Three places copied the **host's** ssl app into the app's
flat BEAM directory: `Deployer.collect_beam_dirs/0`,
`ReleaseAndroid.collect_beam_dirs/0` and the iOS-sim native build. That
directory comes first on `-pa`. The copy was added when the runtimes had no
ssl; every runtime since the crypto-enabled tarballs ships one. So every
Android release and dev install ran the building machine's ssl, and a runtime
upgrade alone fixed nothing in TLS. Review found two iOS siblings:

- The physical-iOS dev build compiled a no-op `ssl` shim into the beams dir
  for LiveView apps, so on a phone their ssl returned `ssl_not_supported`.
  `mix mob.release --ios` reuses that dir.
- That build and the iOS release script also copied the host's
  runtime_tools, asn1 and public_key into `lib/<host-vsn>`. The code server
  takes the highest version, so a newer host could replace the runtime's
  patched public_key.

## Decision

1. Publish a **new** hash, `otp-d199a49a` (the commit of the OTP-29.1.2 tag),
   rather than clobbering `5c9c69fc`, as in
   2026-06-17-otp-hash-elixir-1.20.1.md. erts moves to 17.1.1.
2. Rebuild from a pristine upstream tag, with every build input in this repo:
   - vendored xcomp confs for all five targets;
   - patches 0001–0003. 0003, the iOS `{spawn, LinkedInDriver}` fix, had
     only ever been applied by hand. 0002's marker was wrong: upstream
     already contains `#ifndef NO_DAEMON`, so the patch was skipped.
   - the static `asn1rt_nif.a` via OTP's `static_lib` target;
   - `--disable-year2038` on arm32;
   - the iOS xmerl deps regeneration.

   The `5c9c69fc` tarballs could not have been reproduced from this repo
   alone.
3. Never put host OTP apps, or shims of OTP apps, on the device. Only the
   app, its deps and EEx (Elixir stdlib) are pushed or copied. Everything
   else comes from the runtime, which ships ssl, public_key, asn1,
   runtime_tools and crypto on every target.
   - Deploys and builds delete the host-ssl and shim files an older mob_dev
     left behind, because a deploy otherwise only adds files.
   - `patch_epmd_source/1` now checks for "already patched" at the
     `run_daemon(g)` call site, for the same reason patch 0002's marker had
     to change.
4. Require `mob ~> 0.9.25`. Older mob hard-codes `erts-17.0` in the Android
   launcher, and in the iOS-sim fallback used when `-DERTS_VSN` isn't
   passed, so it can't boot erts-17.1.1. mob 0.9.25 reads the directory at
   runtime. As a Hex requirement it keeps an app's mob and mob_dev in step
   without a doctor check.

## Consequences

- Moving to the new runtime means updating both deps and doing a `--native`
  deploy. Apps pinned to an older mob_dev keep `5c9c69fc`.
- The host's OTP version no longer affects the device's ssl, public_key or
  asn1. That also removes a source of host/device version skew, e.g. ssl from
  a 28.x host running on a 29 runtime.
- OpenSSL 3.5.x point releases and OTP 29.x patch releases are now a rebuild
  from this repo plus a manifest bump. MOB-495's scan reports when one is
  needed.
